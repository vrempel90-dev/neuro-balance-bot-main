`SYSTEM_PROMPT_rendered.md` не менялся. Проверка поведения использует реальный Python pipeline, scripted OpenAI protocol и изолированную CRM. Это не оценка качества настоящей языковой модели.

| Правило | Подтверждение и предел |
|---|---|
| Разговор RU/KK, смешанные и явное переключение | Multi-turn language persistence/switch и KK FAQ; существующие language guards. Полное качество естественной речи и казахский клинический стиль требуют review реальной модели. |
| Жалоба → PROFILE/NON_PROFILE/UNCLEAR | Literal independent expectations, отрицания/родственники/пятка/смешанные жалобы; неизвестное остаётся закрыто. Backend имеет ограниченный проверяемый словарь, не универсальное понимание любой опечатки. LLM извлекает смысл из истории, но не может самостоятельно расширить scope. |
| Пациент отдельно от отправителя | Нормализованное родство, reset patient context, SQLite version boundary, отдельные patient name и sender phone. Все 11 relative cases проверены; автоматический POST родственнику запрещён, пока CRM не умеет подтвердить отдельного пациента. |
| Все факты одного сообщения сохраняются | Возраст/contra/имя/родство/день/время сохраняются даже при UNCLEAR. Прогресс не сбрасывается после FAQ. |

## Что пока не подтверждено

Нет доступного OpenAI API key в локальной тестовой среде; Railway OAuth раскрывает только имена переменных. Поэтому не выполнялись реальные model calls и не заявляется полноценная LLM-проверка. Не создавались реальные CRM-записи, не отправлялись сообщения пациентам, не проводился production deploy. Текущая достоверность всех свободных времён и результатов неопределённых операций (четыре claim-записи, число реальных операций требует сверки) может проверяться только владельцем в CRM.
